Building systems for cumulative intelligence

Agents should improve with experience.

We build memory, provenance and evaluation infrastructure for agents working with changing information.

Explore the work ↓

The problem

Memory is not enough.

A stored answer can be outdated. A successful procedure can fail when the task changes. Keeping more history does not tell an agent what to trust or do next.

The challenge is to connect retained experience to decisions, and to notice when the past has become a liability.

What we are investigating

01 / 04

Decisions

What should the agent do differently?

A previous failure could justify checking an assumption, searching another source or asking a person. How should the system choose that response, allocate its attention and compute, and make the resulting decision inspectable?

02 / 04

Useful state

What deserves to persist?

Facts, procedures and failed attempts have different useful lives. What representation, scope and expiry should each have? The record should preserve where a claim came from and what would invalidate it.

03 / 04

Revision

When should the past lose authority?

A rule that helped yesterday can mislead today. How should a system detect changed conditions, revise inherited state or reset? What knowledge should remain local because of privacy or context?

04 / 04

Evaluation

Did experience actually help?

Compare against a fresh start, additional context or compute, and advice available before the experience. Measure outcomes, repeated errors, cost and escalation as conditions change. A useful experiment must distinguish help, no effect and harm.

Public technical work

Agent Memory Contracts

An agent’s interpretation should not silently become a fact. Agent Memory Contracts is a public Python library for making that boundary explicit.

Source evidence stays linked to a candidate claim. Accepting the claim requires a recorded decision, and the validator rejects a trusted record without the required authorization. The worked reducer example shows acceptance, rejection and an invalid promotion.

Repeated work

Bring a problem that keeps coming back.

Does an agent reconstruct the same context every week, repeat a known mistake or fail when a fact changes? We want to work on recurring workflows where the result can be checked and a person can intervene.

The broader thesis

Intelligence should accumulate.

Learning costs time, attention and failed attempts. The essay asks what should survive that investment, how it can pass between systems and when it should lose authority.
